# Glossary

Terms used across this project, with the specific meaning they carry here.

## Neuroscience

**Neuron** — a cell that transmits electrical signals. In this project, one
modeled unit. Target count: ~86 × 10⁹.

**Synapse** — a connection from one neuron to another. In this project, one
edge in the connectome. Target count: ~10¹⁴.

**Connectome** — the complete set of connections in a nervous system. Used here
in two senses, always disambiguated: a *measured* connectome (reconstructed from
data) and a *synthetic* connectome (generated from statistical rules).

**Mesoscale connectome** — connectivity between brain regions, typically from
tracer injections. Coarse: it says region A projects to region B with strength
*w*, not which neuron connects to which.

**Microscale connectome** — neuron-to-neuron connectivity from electron
microscopy. Fine, but only available for small volumes and non-human species.

**Parcellation** — a division of the brain into named regions. A parcellation is
a choice, not a fact; different atlases disagree.

**Cell type** — a classification of neurons (e.g. excitatory pyramidal,
parvalbumin interneuron). Composition varies by region.

**Excitatory / inhibitory** — whether a synapse increases or decreases the
postsynaptic neuron's firing probability. Encoded as `sign` = +1 / −1.

**Spike** — an action potential; the discrete event a neuron emits. The
simulation's unit of signalling.

**Membrane potential** — the voltage across a neuron's membrane, in mV. The
primary state variable of every neuron model here.

**Refractory period** — the interval after a spike during which a neuron cannot
fire again.

**Fidelity** — how detailed a neuron model is. A point neuron is low fidelity; a
multi-compartment morphological model is high fidelity. Cost scales roughly with
fidelity.

## Modelling

**LIF (leaky integrate-and-fire)** — the simplest spiking neuron model: a leaky
integrator with a threshold and a reset. Implemented here as a placeholder.

**EIF / AdEx** — exponential and adaptive exponential integrate-and-fire;
richer spike-initiation and adaptation dynamics. Aspirational.

**Multi-compartment model** — a neuron represented as many coupled compartments
with a morphology. Aspirational.

**Point neuron** — a neuron with no spatial extent; a single state variable.

**Plasticity** — activity-dependent change in synaptic strength. STDP
(spike-timing-dependent plasticity) is the canonical example. Aspirational.

**Fidelity tier** — the model class assigned to a region. Declared per region,
never globally.

## Engineering

**COO (coordinate list)** — sparse storage as parallel `pre`/`post`/`weight`
arrays. The current connectome format.

**CSR (compressed sparse row)** — sparse storage as per-row index ranges. The
planned format for fast per-neuron edge lookup.

**Sharding** — splitting a dataset across files or machines so it can be
streamed rather than loaded.

**Cut edges** — synapses that cross a partition boundary. Their count determines
the communication cost of a distributed run.

**Event-driven delivery** — delivering synaptic current only for edges whose
presynaptic neuron fired, instead of scanning all edges.

**Struct-of-arrays** — storing neuron state as parallel arrays rather than a
list of objects. The prerequisite for vectorised and GPU execution.

**Backend** — a pluggable implementation of the stepping kernel (NumPy, Numba,
JAX, MPI). Planned.

**Reference implementation** — the slow, obviously-correct version that every
fast backend must match bit-for-bit.

## Project vocabulary

**Measured** — derived from observation. Carries `measured: true`.

**Synthetic** — generated by a rule, not observed. Carries `measured: false`.

**Provenance** — the record of where a piece of data came from. Mandatory for
every dataset.

**Run record** — the artefact capturing config, seed, code version, datasets and
fidelity map for a simulation. Planned.

**Aspirational** — described in the roadmap, not present in the code. The README
marks these explicitly, and so must any document that mentions them.

**Honesty rule** — the project's first principle: never claim a capability the
code does not have, and never mix measured and synthetic data silently.
